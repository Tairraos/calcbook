# 界面与交互规范

状态：有效 · 负责人：项目维护者 · 核验日期：2026-09-29

## 方向

Numi 的“左边思路、右边答案”是交互参照；Calcbook 默认采用独立的纸白与苔绿视觉，提供纸白与午夜两套配色。主体是实际工作区，不使用营销首页、指标卡片墙或复杂工具栏。

两列：230 px 笔记导航、弹性编辑区域。普通计算器是独立的浮动子窗口。顶栏放「随手算」「计算器」两个按钮，同为图标加文字的轻工具样式（保存失败时在按钮左侧显示「尚未保存」）。「随手算」打开内存里的临时算稿（见「随手算」），打开时按钮高亮绿；「计算器」开关子窗口，子窗开着时高亮绿。格式化自 1.5.6 起移到笔记工具行（见「编辑器」）。格式化走编辑器原编辑路径，Cmd/Ctrl+Z 在无后续编辑时撤销整个格式化（应用内撤销，用户再编辑即作废）。窗口最小 800×640，侧栏不随窗口大小自动隐藏或变为抽屉，笔记区不因 resize 改为全宽；收起与展开只经顶栏按钮。布局不随窗口尺寸做响应式变化（0.6.11 起删除了全部布局断点；唯一例外是查找输入框在 720 px 以下的浏览器预览宽度收窄避让结果列），基础样式在任意窗口大小一致，窗口缩放只增减编辑区弹性空间。

## 随手算

顶栏「随手算」按钮（SquarePen 图标 + 文字）打开一篇内存里的临时算稿（1.5.6 起）：不创建文件、不进入工作区、不经过持久化层，app 退出即消失。只有这个按钮能打开它——点击时侧栏当前选中的笔记失焦（侧栏无高亮项），面包屑只显示「随手算」，标题框显示只读的「随手算」（随手算没有文件名，不可改名）；再点普通笔记、新建笔记或切换我的笔记/废纸篓 tab 都会离开随手算——1.6.4 起点当前已激活的 tab 同样离开，且随手算打开期间两个 tab 的高亮都熄灭（启动恢复落在新随手算时「我的笔记」tab 不再保持高亮）。App 运行期间内容一直在内存里：切去别的笔记再点「随手算」，原样恢复；首次点开正文是提示行加一个空行（「# 随手算笔记不会保存，app 退出即消失」+ 空行），打开随手算（按钮与启动恢复）时光标都定位在文末的空行上，聚焦编辑器直接开写（1.6.2 起）。除以下三点外，随手算与普通笔记能力完全一致——计算、查找替换、格式化、复制、计算器写入都可用；① 不保存（编辑不触发写盘，保存状态不受影响）；② 没有历史：历史弹窗打开永远是空态，也不会产生任何留档；③ 不能移到废纸篓（删除按钮禁用，提示不会保存为文件）。右侧结果列照常计算；用户想留存就手动复制全文，粘贴到新笔记或文件。

**启动恢复（1.6.0 起）**：app 记住上次打开的文件（工作区 `activeId`），启动时直接恢复它。`activeId=null` 是明确的视图约定——「当前显示的不是我的笔记里的笔记」：上次退出在随手算、上次在废纸篓视图、上次笔记已不存在（外部删除等），以及首次打开（新工作区 `activeId` 即为 null），启动时都打开一篇**新的**随手算（内存内容不跨进程，新的即提示行加空行，光标落在空行上）。打开随手算与切到废纸篓 tab 都会把 `activeId` 置空持久化；切回我的笔记 tab 时若 `activeId` 无效则落回第一篇可用笔记。判定是幂等的启动逻辑，不回写工作区。

收起/展开笔记列表的按钮常驻在顶栏面包屑最左侧（「我的笔记」左边），随状态切换收起/展开图标并同步 `aria-expanded`。侧栏通过自身宽度 220 ms 过渡平滑收放（grid auto 列跟随），收起完成后 `visibility: hidden` 移出 Tab 序。动画尊重 prefers-reduced-motion。侧栏内笔记列表使用 3 px 极细滚动条，画在右侧留白区不压缩卡片，静止时隐藏、悬停列表时出现。

搜索框下方的列表标题行是「我的笔记」「废纸篓」两个 tab（`aria-pressed` 表达当前项；按钮无下边框、顶角圆、底边贴住标题行的下边线——下边线即按钮的下边框效果，右侧动作图标保持垂直居中），切换下方的文件列表；行尾动作图标随 tab 变化——「我的笔记」显示「新建笔记」（+），「废纸篓」显示「永久删除全部」（垃圾桶）且图标左侧显示废纸篓内笔记数。文件列表下方不再设新建按钮，侧栏底部不再设废纸篓与语法速查入口，底部只保留设置行；0.6.9 起语法速查入口移到笔记区标题工具行（见「语法速查」）。

## 计算器子窗口

普通计算器是主窗口之外的一个浮动子窗口，由 Rust 按需创建（label `calculator`，加载同一前端包的 `?view=calculator` 路由）。

- **单实例**：重复点击「计算器」不会开第二个窗口；已最小化时点击会还原、重新居中并聚焦，已打开时仅聚焦。窗口按需创建且创建时隐藏——tauri 默认「建窗即显示」，若不显式 `.visible(false)`，首下点击会因 `is_visible()` 为真而把刚建好的窗口立即收起，表现为要点两下才出计算器。
- **窗口形态**：与主窗同为 Overlay 标题栏（红绿灯保留、标题文字隐藏，每次打开都重新居中到主窗口正中间，最小化还原亦然）——仅 macOS；Windows/Linux 用系统默认标题栏（`title_bar_style` / `hidden_title` 是 macOS 专属 API，其他平台不调用）。macOS 上居中用原生 `NSWindow.setFrame(_:display:)` 直接读写两窗的真实点坐标——tao 的 `set_position` 底层是 `setFrameTopLeftPoint`，被 AppKit 约束在窗口当前屏幕内，主窗移到另一块屏幕后定位会被静默忽略，故不能走 tao。居中结果必落在主窗所在屏幕内，主窗在缩放比不同的屏幕（内置 Retina + 外接 1x）同样对齐。顶部 40 px 是拖拽区：整条 `data-tauri-drag-region` 覆盖全宽（含侧栏上方），按住其中的非交互内容即可移动窗口。该属性的 `start_dragging` 由 ACL 逐窗口授权，计算器窗口的 capability 必须带 `core:window:allow-start-dragging`；漏授时 Tauri 注入脚本的 invoke 被拒绝，拖拽静默失效。宽高固定，窄态 300×500，展开「最近计算」侧栏后 600×500——计算器主体固定 300 px 面积不变，侧栏 300 px；不允许最大化（macOS 绿点 zoom 禁用），用户不能手动 resize，窗口无滚动条。
- **关闭语义**：红绿灯「关闭」由 Rust 转为隐藏，算式与历史保留；从主窗再次打开即恢复。app 退出后进程结束，再打开是全新状态。主窗口销毁时计算器一并销毁。
- **自动收起**：失焦（含最小化）5 分钟未被再次激活，前端调用 Rust 隐藏窗口。
- **主窗按钮**：子窗口开着（不论是否最小化）时「计算器」按钮高亮绿，由 Rust 在显示/隐藏时推送 `calculator://visible` 事件驱动；未打开为普通颜色。浏览器预览点击提示仅桌面版可用。
- **写入当前笔记**：子窗口通过 `calculator://insert` 事件把原算式发给主窗，由主窗插入当前行之后，主窗显示「算式已写入笔记」。
- **最近计算**：「历史」按钮（书本图标 + 文字）右齐在顶部拖拽区，锚定固定 300 px 的主体列而不是窗口右缘：展开侧栏时窗口向右加宽，按钮留在原位、不会跑到侧栏上方；切换显示/隐藏侧栏。侧栏 300 px，内容可滚轮滚动但不显示滚动条。标题行「最近计算」高度固定，右侧的清空动作是带常显边框的「清空」文字按钮（与「历史」开关同款小按钮，无图标），仅在有历史时出现——标题位置不随清空/有内容变化。历史项 hover 时右侧出现笔形图标，点击把该条算式插入主窗笔记；点击条目其余部分仍是用结果续算。没有「写入当前笔记」按钮。
- **主题**：与主窗始终一致——桌面版启动时由主窗在子窗打开瞬间推送当前配色（工作区主题存在文件系统而非 localStorage），主窗切换纸白/午夜时经 `calculator://theme` 事件同步；浏览器预览读 localStorage。

## 窗口与标题栏

桌面版在 macOS 使用 Overlay 标题栏并隐藏原生标题：内容延伸到标题栏区域，主列顶栏（面包屑、保存状态、计算器开关）即标题行，与侧栏品牌行同为 `data-tauri-drag-region` 拖拽区。侧栏内容从红绿灯下方 46 px 处开始，品牌 logo 左对齐、不再横向避让交通灯；仅侧栏收起时顶栏左侧保留 84 px 让位红绿灯。Windows/Linux 使用系统默认标题栏：`native-titlebar` 类只在 macOS 桌面版加上，其他平台不预留红绿灯空间、也不加侧栏顶部内边距。由于该属性只对标记元素本身生效，平台层在桌面版额外安装 mousedown 处理器：按住区域内任意非交互内容（面包屑文字、logo、空白处）即可拖动窗口；按钮、输入框等交互元素不受影响。浏览器预览没有该处理器，布局不变。`document.title` 仍提供窗口标题供 Mission Control 等系统界面使用。窗口打开尺寸默认为最小 800×640；关闭时把当时的逻辑尺寸记入配置目录 `settings.json` 的 window 字段（1.4.7 起不再写默认数据目录的 `window.json`，旧文件兼容读取并在首次保存后清理），下次启动恢复（钳制到最小尺寸），仅记尺寸不记位置。

## 视觉事实来源

配色统一在 [theme.css](../../src/theme.css)，布局在 [styles.css](../../src/styles.css)。theme.css 每个颜色变量带行内注释说明其用在界面哪些位置；新增变量时同步补注释。本机系统字体用于 UI，系统等宽字体用于算式；无需在线加载字体。强调色表达可计算内容与结果，错误同时有图标和文字。

保持轻边框、少量圆角、克制阴影与稳定悬停。按键区使用熟悉的四列布局，等号为主强调。图标统一使用 Lucide。侧栏品牌使用 `src/assets/dark.png` / `light.png`（270×50 的 2x 资产，显示 135×25）：午夜显示 dark，纸白显示 light，随主题即时切换；字标右上角以 10px 次要色显示构建时注入的版本号（`v版本号`），启动即可辨认当前构建，颜色随 `--muted` 明暗自适应。

## 设置与主题

左下角设置行以设置图标进入设置；同一行最右侧是太阳/月亮切换按钮（30×30 图标按钮，与行右缘齐平），浅色显示月亮（切换到深色），深色显示太阳（切换到浅色）。`⌘/Ctrl ,` 也可打开设置。设置使用原生 modal dialog，包含文件存放位置、编辑历史（每笔记历史空间 KB 输入 + Info 悬停提示）、格式（空格与数字三栏开关、单位写法、单位制）与关于信息；弹窗最高 565 px，内容超出时标题与底栏固定、中间区域滚动。改动立即应用并按真实保存状态反馈。计算器模式设置已移除（只保留边栏形态），旧工作区中的 calculatorMode 字段读取时忽略。

格式设置原为独立弹窗，0.4.0 起提供全文格式化（空格与数字、单位写法、单位制，见 [计算语言契约](../product-specs/calculation-language.md)），0.6.1 起并入设置弹窗；顶栏只保留「格式化」动作。1.4.3 起格式区不再有「格式」标题与引导句：拆为「格式化 - 空格与数字」section（三栏开关）与单位 section（「格式化 - 单位写法」「格式化 - 单位制」两个单选组共用一个 section），行尾的自由/制式说明保留。0.4.0 已移除旧版「光标离开当前行自动改写单位」的行为，改为显式按「格式化」整理整篇。

| 配色 | 标识 | 明暗 |
| --- | --- | --- |
| 纸白 | light | 浅色 |
| 午夜 | dark | 深色 |

切换按钮是有可访问名称的图标按钮，切换立即生效并写入工作区。0.6.11 起主题标识为 `light`/`dark`；0.6.10 及以前的 `paper`/`midnight` 与更早的六套主题在读取时迁移：`paper`/`light`/`sand`/`mist` 为 `light`，`midnight`/`dark`/`forest`/`graphite` 为 `dark`；未知主题仍报错。设置弹窗不再包含主题配色块。About 展示 app 版本、编译时注入的构建时间与可打开的 GitHub 链接。浏览器预览的文件夹按钮禁用并说明实际存储位置；不能显示虚假的文件保存成功。

## 右键菜单与永久删除

侧栏笔记名右键弹出操作菜单：定位（桌面版用系统文件管理器显示所在 .txt，浏览器预览提示仅桌面版）、导出（另存为，与保存同构带结果）、删除（移到废纸篓）。菜单在光标处渲染，点击任意项、菜单外的任意位置或 Escape 即关闭（1.6.3 修复：菜单外点击关闭此前只有文档约定、未实现）。

废纸篓 tab 的动作图标固定为「永久删除全部」垃圾桶（左侧显示废纸篓内笔记数）；「我的笔记」tab 的动作图标是「新建笔记」。废纸篓笔记的标题工具区在「恢复」旁增加「永久删除这篇笔记」。编辑器工具行的「移到废纸篓」1.4.4 起也先弹确认（列明标题，说明可恢复）。永久删除类操作都先弹确认（列明篇数与标题），确认后从工作区移除笔记，Rust 保存时按新旧元数据差异物理删除对应 .txt 文件。右键菜单的删除仍只是移到废纸篓（无确认）。废纸篓不接受新建（1.5.4 起）：空列表时主区只显示「没有被丢下的想法 / 移入废纸篓的笔记会保留在这里。」，不出现「新建笔记」按钮，面包屑右段显示「空」（「废纸篓 › 空」）而非默认的「新的一页」——废纸篓里的笔记只能由「我的笔记」删除过来；「我的笔记」的空状态仍保留新建入口。

目录切换期间禁用重复选择和设置关闭，先完成待保存写入，再复制文件、提交新位置；取消系统对话框保持原设置。失败原因显示在设置内部。

## 注释渲染

`#` 与 `//` 作用一致：整行与尾部注释都用注释颜色渲染，计算结果只在右侧结果区；保存文件时尾部注释保留在行尾、结果写在算式之后（`5 kg = 36 # 备注`）。

## 聚焦反馈

两个文本输入区（搜索框、编辑器）不显示描边型 focus ring：搜索框聚焦用所属容器的背景色变化表达，编辑器聚焦无任何描边（0.6.11 起），仅保留文本光标；两者的文本光标使用纯黑（纸白）/纯白（午夜）以获得最高对比；光标粗细由浏览器决定，不可配置。计算器算式框自 1.5.5 起不可聚焦（键盘整体接管，见下节），算式屏底色改随窗口焦点变化表达「可输入」状态。1.5.1 起所有文本输入框（含查找替换浮动条、设置项）一律不画聚焦外框——光标闪烁已足以表达焦点；按钮与链接的键盘 focus ring 保持可见。

## 计算器输入与显示

窗口有焦点时键盘整体接管（1.5.5 起）：所有按键都默认输入算式——回车是等于、`C`/`c` 是清空、`x`/`X`/`*` 都是乘号、`/`/`\`/`÷` 都是除号（显示为 `×` `÷`），数字、`.`、`+`、`-`、`%`、括号、Backspace、`=`、Escape 直取；表外的键（含其余字母）一律忽略无反应，Tab/空格被拦下不挪焦点、不触发按钮，Cmd/Ctrl/Alt 组合键留给系统快捷键。算式框只读且不可聚焦（`readOnly` + `tabIndex=-1`，鼠标按下也不聚焦）：没有光标进入就不会激活输入法，计算器窗口不可能进入中文输入。键盘按下时对应按键显示与鼠标按下同款按压态（keydown 加 `is-pressed`、keyup 撤、窗口失焦即清），并播放 WebAudio 即时合成的按键音（无音频资源文件，长按自动重复不重复发声）；鼠标按下按键同样有按压态与按键音。按键为阴影立体样式（1.6.6 起，1.6.8 简化投影并重构类名）：投影固定为「底部 2px 实边 + 2px 模糊落地影」两层，颜色来自 theme.css 的 `--key-shadow` 等平面色变量，投影结构写在 styles.css 的 `key-num`/`key-func`/`key-opt`/`key-equ` 四类上；圆角 10px，悬停只变色（浅色更暗、深色更亮，不位移），按下（鼠标与键盘 `is-pressed` 同款）整体下沉 2px、投影保留；运算符与等号键为桔色（白色符号），数字与功能键沿用纸白/午夜键面，深浅主题都有细边框勾出键面轮廓（浅色浅灰、深色更亮的灰，桔色键同色系勾边）。计算器窗口内的文字（按键符号、屏显、提示）不参与拖选（1.6.7 起，`user-select: none`）。错误信息在顶部「随手算一算」槽位原位替换显示（单行省略），消失后原文案恢复——算式屏高度不变，数字键盘不随之抖动。等号后算式框与结果列同时变成结果值（与显示一致的四位精度），续算、退格与「最近计算」的「用结果续算」都在显示精度上进行；历史条目仍显示原始算式。输入与结果的宽度上限为整数 16 位、小数 4 位（1.6.10 起，不使用科学计数法）：输入时封顶——整数到 16 位、小数到 4 位后继续按数字无反应（1.6.11 起）；写下的数字超宽报「数字宽度超限」，计算结果超宽报「计算结果数字宽度超限」（1.6.11 起区分文案），都在错误槽位显示。按文字实际宽度缩小字号，禁止横向滚动，不裁切负号。

## 语法速查

入口在笔记区标题工具行（`note-tools`）最右侧（1.5.6 起，此前在最左侧），是仅显示带圈问号的图标按钮；0.6.8 及以前在侧栏底部。0.6.9 起侧栏底部不再保留该入口。

语法速查弹窗按 tab 分组：「示例」（可点击写入笔记的例子）、「函数与常量」、「汇总与变量」、「关键字」、「单位与符号」——后四个是保留字参考表，写法/作用/例子三列，内容与 [计算语言契约](../product-specs/calculation-language.md) 一致。tab 使用原生 tablist 语义，方向键左右切换，焦点可见；表格文字在明暗主题下都保证对比度。单位清单（「单位与符号」与「保留字 · 单位」）的写法列在 `；` 后换行、过长的一项再按空格折行；表格最小宽度 480 px，「作用」列保留约 6 个汉字的宽度，因此整表不再撑出横向滚动，只有在窄窗口（面板宽度小于 480 px）才在面板内横向滚动而不是把列压扁。

## 编辑器

原生 textarea 保留选择、粘贴、撤销与中文输入法；其下的无交互文本镜像只承担着色。源文本与结果固定 23 px 行高并处于同一滚动区域，不允许结果和行错位。长行水平滚动而非折行，避免一行对应多个高度。结果列宽度随内容自适应（1.6.10 起）：最窄维持 135 px，内容显示不下时自动加宽，最宽 220 px，再放不下的部分在单元格内省略；列头「结果」标签贴右缘，始终与右对齐的结果对齐。编辑区滚动条贴窗体最右缘（1.4.5 起滚动容器不再留右侧 margin，结果列间距由自身 padding 承担），且垂直滚动条常驻（`overflow-y: scroll`，透明轨道）——文字增多滚动条出现时布局不突变。

笔记标题即文件名主干（无扩展名）：标题输入框、面包屑、侧栏列表与系统窗口标题显示的都是文件名（统一的 `.txt` 扩展名隐藏）。标题输入只改草稿，失焦或回车提交改名（Escape 放弃），由存储层清洗非法字符、给撞名自动加序号并反馈实际名称；正文里的 `#` 行只是内容小节标记，不再是标题来源，改名不动正文。标题输入框聚焦不画任何外框（1.5.4 起，`outline: none`）——1.5.1 移除共享的绿色 `:focus-visible` 规则后浏览器默认聚焦框（Chrome 蓝色）接管，现明确关闭；所有文本输入框统一以文本光标表达焦点，按钮与链接的键盘焦点框保留。编辑区无选区时 Cmd/Ctrl+C 复制整行、Cmd/Ctrl+X 剪切整行（剪贴板含行尾换行，粘贴即整行落位；删除走 textarea 原生撤销栈）；有选区时保持原生复制/剪切。

编辑器上方固定列头「笔记与算式 / 结果」在非废纸篓视图中带便捷输入按钮（小方形 `×`、`÷`），点击在光标处插入对应符号并把焦点交还编辑器；输入框未聚焦时追加到正文末尾。除号与乘号按钮只负责输入，格式化不会替换 `÷` 与 `/`（`/` 常用来表达分子/分母），`x` 与 `*` 则在格式化时统一成 `×`。笔记工具行的导入/导出按钮在 1.2.0 移除（导出仍可经侧栏右键菜单使用），同位置改为「历史记录」图标（calendar-clock）。1.5.6 起工具行固定五个图标，顺序为：查找替换（search，开关）、格式化（sparkles，自顶栏移入）、历史记录（calendar-clock）、删除（trash-2；废纸篓视图为恢复 undo-2 与永久删除 trash-2）、语法速查（circle-help）。

底部状态栏左侧显示「n 条计算」，存在错误行时以「|」分隔追加红色「n 处待检查」按钮（1.5.2 起可点击、1.5.4 起分隔符为普通文字色的管道符）：点击把光标依次停在每个错误行的行尾并滚动到可见，循环往复，焦点还回编辑器、状态栏行号同步。因为点击会让编辑器失焦，遍历序号不读当前光标位置，由独立的序号记录维护，切换笔记时重置。光标停在错误行时（1.5.3 起），再以「|」追加「第 k 处：出错原因」（k 为该行在错误行中的序号），超长省略（max-width 42vw）。分隔符与出错原因都在按钮之外，hover 下划线只落在可点击的「n 处待检查」上（1.5.4 起，此前前导「· 」随按钮一起带下划线）；分隔符用负外边距抵消父级 6 px gap，收成左右各 3 px。

结果列的错误行（1.5.3 起）：「⚠ 检查算式」在结果列内左对齐（计算结果仍右对齐），是可点击按钮——点击把光标定位到该行行尾、焦点还回编辑器并滚动到可见，与状态栏「n 处待检查」共用同一跳转函数。出错原因以自定义浮层展示（按钮不再带 title 属性，浏览器原生提示已移除）：单行 nowrap、宽度随内容弹性（上限 min(480px, 70vw)，超出省略）、与编辑器同色的纸面底色与墨色文字、默认边框色描边、小留白（3px 8px）。浮层方向按 hover/聚焦时的真实位置判定：向下空间不足（距滚动容器底缘 < 提示高度 + 8px）改向上展开；从行左缘向右会超出滚动容器右缘时，改从行右缘向左展开（按错误文本长度估算宽度，CJK 约 13px/字）。

## 查找替换

⌘/Ctrl+F 在编辑区右上打开浮动条（1.5.0 起），笔记工具行的查找图标（历史记录左侧，1.5.1 起）是同一入口，且是开关（1.5.4 起）：浮动条开着时再点即关闭并把焦点还回编辑器，图标提示随之在「查找替换（Cmd+F）」与「关闭查找替换（Esc）」间切换；Esc 或 × 关闭并把焦点还回编辑器；打开时编辑器内的单行选区自动带入查找框，无选区保留上次查询。浮动条上移到列头行高度（1.5.1 起），展开替换行不再压住首行正文与结果列。作用域是当前笔记正文，跨笔记搜索仍由侧栏 ⌘K 过滤承担。查找框右侧三个开关与 VS Code 对齐：区分大小写（默认关）、全词（`\b` 边界——中文无词边界，全词对纯中文词不生效）、正则表达式（ASCII「.*」字形，1.5.1 起；lucide Regex 图标圆点悬空像中文句号，弃用）；非法正则时输入框标红、计数区显示「正则错误」，不清空正文。计数区显示「当前/总数」，无匹配显示「无结果」；Enter 下一个、Shift+Enter 上一个，首尾回绕；正文被手动编辑后匹配与当前序号即时重算。全部匹配在镜像层叠加淡金底色、当前匹配加深（`--find-match` / `--find-match-active`，明暗主题各一）；零宽匹配（如 `a*` 的空命中）渲染为 2 px 指示条。输入法组合中的 Enter/Escape 属于组词，不触发导航或关闭。文本输入框（含本浮动条）聚焦不画绿色外框（1.5.1 起），光标闪烁已足以表达焦点。

替换行经查找行左侧箭头展开；废纸篓只读视图只能查找，不出现替换入口。Enter 或替换按钮替换当前匹配并自动前进到下一处；单个替换走 textarea 原生编辑路径（execCommand insertText），Cmd/Ctrl+Z 逐步可还原。全部替换一次写入整篇：替换前先留档进历史（破坏性操作），替换后一次 Cmd/Ctrl+Z 整体还原。撤销只留一条轨道（1.5.1 修正）：execCommand 成功时原生撤销栈接管，应用内撤销（formatUndoRef）让位；仅 execCommand 不可用的回退路径（React 状态替换）才挂应用内撤销——双轨并存时连续 Cmd+Z 会把原文复制一份（1.5.0 实测 bug，格式化同款路径一并修正）。替换结果超过笔记长度上限时不执行并提示。跳转不抢焦点：查找框输入期间焦点留在浮动条，滚动定位由镜像行真实布局计算（垂直精确到行，水平按列宽估算保证匹配可见）。

## 历史记录

笔记工具行的 calendar-clock 图标打开固定尺寸弹窗：右上角有关闭叉叉（打开时焦点落弹窗容器，不落在叉叉上），左侧列出当前笔记的全部历史（只显示时间：秒级快照显示「月日 时:分:秒」、整点归档显示「月日 时」），右侧预览选中内容；每个条目带 calendar-arrow-up 恢复按钮与 trash-2 删除按钮，删除先弹确认（列明时间与不可恢复），确认后真实删除该快照文件并刷新列表。恢复 = 当前内容先按规则留档（得到独立的秒级快照），再把该历史版本加载进编辑器；当前内容与最近一次留档相同（例如刚恢复又换看另一份、未做编辑）时不重复备份。

历史以文件名同名目录管理：数据目录 `history/<文件名主干>/<年-月-日-时-分-秒>.txt`，本地时间的秒级时间戳即文件名，当前小时内可以有多份（最多每 10 分钟一份、破坏性操作前各一份）；超过一小时的部分在每次留档与打开弹窗时整理——每小时多份只保留最后一份并改名为整点（`…-时-00-00`，旧版 13 字符整点文件名兼容参与整理）。仅空行与空格的内容视为空文件不留档，有文字或数字都算实质内容。留档时机：有实质编辑后每 10 分钟、切换笔记、关闭应用、破坏性操作之前——破坏性操作指格式化，以及一次性剪切/删除 5 行及以上（选区跨至少 4 个换行，在动作发生前留档）；「实质编辑」以最近一次留档内容为基线。单篇全部历史总量上限在设置弹窗「编辑历史」区配置（KB 输入，默认 128，0 = 关闭；1.4.2 起以常驻说明文字交代 0 的语义与淘汰规则，不再用悬停图标），超出按时间从最早淘汰，最新一份永不淘汰（超大单篇快照可超限，历史不至于全空）。设为 0 不立即清空：编辑到哪篇，留档调用即清空那篇的既有历史；重启应用时启动扫描清空全部历史——重启前用户可以反悔改回来。启动扫描同时清理 `history/` 下不再对应任何笔记的孤儿目录。改名时历史目录跟随文件名，永久删除时历史目录一并删除；废纸篓进出不影响历史。浏览器预览以 localStorage 承载同一套逻辑（无整理、淘汰与启动清理），便于预览态验收。

结果显示（1.4.6 起约定）：数字与单位间空格实时跟随设置里的「数字与单位空格」（关 = `5km`、`99.5CNY` 紧贴，开 = `5 km`、`99.5 CNY`；正文经「格式化」对齐同一设置；复制用的精确值 raw 恒为 `5000 m` 形态不带千分位，写入 .txt 的 `= 结果` 也保持带空格的原有格式，Numi 兼容不变）；千分位逗号在设置里拆为「笔记千分位逗号」（格式化写入正文）与「结果千分位逗号」（只影响结果列显示，改动立即生效、无需格式化，默认开）。计算器窗口的显示与结果列一致（紧贴、有千分位）。结果是有可访问名称的复制按钮。行级错误可通过鼠标悬停或键盘聚焦查看。辅助镜像不进入可访问树，读屏只读取真实文本与结果。

## 必须检查

- 主界面的新建、搜索、编辑、复制、导入导出、废纸篓恢复与计算器都需要真实行为。
- 随手算不落盘：编辑随手算不触发保存、数据目录不出现新文件；历史弹窗永远是空态；删除按钮禁用；切走再点顶栏「随手算」原样恢复内存内容。
- 普通计算器子窗口的键盘接管只发生在子窗口内（独立窗口）；主窗编辑器的数字键与输入法事件不受计算器影响。
- 所有图标按钮具有 title 与 aria-label；焦点可见；帮助与设置弹窗共用原生 modal dialog，弹窗打开时焦点落在弹窗容器上（不落在关闭按钮），Tab 再进入内部控件。
- 明暗主题都可读；主文本与次要说明保证对比度，装饰性行号不承载独立含义。
- 尊重 prefers-reduced-motion。布局固定不随窗口尺寸响应式变化：在最小 800×640 与大窗口下核对界面一致，不能产生页面水平溢出。
- 自动保存反馈必须真实；出错不能用成功 toast 掩盖——保存失败走「尚未保存」与错误横幅；失败/超限类轻提示（1.6.4 起）以警示图标与错误色底渲染，不与成功提示共用 ✓ 样式。

当前 textarea 镜像是有意的轻实现。语法补全、多光标、超长文档虚拟化出现真实需求时再评估编辑器库，见 [技术债务](../exec-plans/tech-debt.md)。
