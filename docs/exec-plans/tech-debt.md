# 技术债务与后续路线

状态：有效 · 负责人：项目维护者 · 核验日期：2026-09-07

| 优先级 | 缺口 / 有意简化 | 何时处理 | 完成标准 |
| --- | --- | --- | --- |
| P1 | Windows/Linux 未做原生验收，当前 bundle 目标为 macOS | 扩大平台时 | 系统依赖、构建配置、存储与 UI 在目标系统验证 |
| P1 | 未签名、公证与自动更新 | 首次向其他用户发行前 | 签名构建、安装/升级/回滚与数据保留验证 |
| P1 | 原生窗口关闭已保护，系统强制退出/断电仍可能丢失最后一次未完成提交 | 正式发行前 | 实测系统退出、恢复；给出可重复的崩溃恢复用例 |
| P1 | 恢复 `.bak` 需要按操作文档手动处理，只有一份上一快照 | 用户需要多版本恢复时 | 明确版本保留规则和可视化恢复，不静默覆盖 |
| P2 | 每次修改重算整篇、保存完整 JSON；超长笔记没有虚拟化 | 300 行性能预算失败或出现大文档反馈 | 以基准驱动 AST 缓存/增量求值和存储策略，不先引入数据库 |
| P2 | mathjs 使用完整构建，首屏包偏大 | 冷启动或安装体积成为瓶颈时 | 用自定义工厂/按需加载降低体积，保留契约用例 |
| P2 | 自动化覆盖纯逻辑和原生存储；UI 场景目前由浏览器工具执行 | 交互稳定、开始频繁改 UI 时 | 将关键流程接入持续浏览器回归，失败保留截图与控制台 |
| P2 | 计算器历史仅会话内；重复等号不重复运算 | 用户实际需要时 | 明确标准计算器连续运算语义，再扩展状态测试 |
| P2 | 目录选择遇到不同的已有工作区会拒绝覆盖，尚无合并/切换流程 | 用户需要管理多份工作区时 | 先审阅冲突与备份方案，验证中断与回滚均不丢失数据 |
| P2 | 文本判定为算式的启发式可能把含运算符的说明识别为错误 | 收集真实笔记样本后 | 样本变为回归用例；保持错误可见，不静默忽略未知符号 |
| P3 | 语法补全、多光标、行折叠未实现 | 笔记编辑交互形成需求时 | 评估原生 textarea 上限后再选编辑器库 |
| P3 | 实时汇率、时区、完整科学模式、同步、插件 | 用户确认相应产品范围后 | 单独规格、来源与离线行为、最小权限和验收测试 |

不以增加目录、抽象层或测试数量作为还债成果；以具体缺口关闭和已有流程不回归为准。

产品与计算功能的未完成清单、当前行为和验收条件同步记录在 [计算语言文档](../product-specs/calculation-language.md)。更改完成状态时同时更新该文档和质量证据。
