# Harness 工作闭环

状态：有效 · 负责人：项目维护者 · 核验日期：2026-09-07

本项目把可读的环境、明确的意图与可执行反馈放在一起。原则来源于 [OpenAI 原文调研](references/research.md)，实现按当前产品规模裁剪。

## 1. 获取上下文

从 [AGENTS](../AGENTS.md) 进入。产品问题读规格，计算问题读语言契约，边界问题读架构。复杂任务建立执行计划，写出具体输入、预期行为和不可改变的条件。尚未完成的产品/计算功能必须出现在 [计算语言文档](product-specs/calculation-language.md) 的未完成表中，并关联计划、测试或债务；区分“未实现”“已编码待验收”和“已验证”。

## 2. 启动独立环境

```sh
pnpm install --frozen-lockfile
CALCBOOK_PORT=1430 pnpm dev
# 或：同一 worktree 内另选端口运行桌面
CALCBOOK_PORT=1430 \
CALCBOOK_CONFIG_DIR="$PWD/.calcbook-data/config" \
CALCBOOK_DATA_DIR="$PWD/.calcbook-data/workspace" \
pnpm desktop
```

浏览器预览按端口隔离 localStorage。桌面必须同时设置上述两个绝对路径来隔离回归数据；不设置时，开发版与发行版都使用 `~/.calcbook` 或用户选定目录。显式隔离后不会从正式目录迁移笔记。Tauri devUrl 随端口同步；不清空或改写真实笔记来“修复”测试。

## 3. 执行反馈

| 命令 | 能发现什么 |
| --- | --- |
| `pnpm check:repo` | 文档断链、缺少元数据、不可达文档、过期提醒、架构依赖越界、危险执行、发行版本和项目链接漂移 |
| `pnpm lint` | 格式、类型可读性、React 和可访问性错误 |
| `pnpm typecheck` | TS 模块与类型边界 |
| `pnpm test` | 精确计算、x/括号别名、百分比/汇总、显示上限与续算精度、旧配置迁移、数据边界 |
| `pnpm build` | 可分发前端资源 |
| `pnpm check:native` | Rust 格式、clippy、原子写入、备份、旧目录迁移、目标冲突与配置提交失败保护 |
| `pnpm bench` | 300 行重算的 p95 是否超过 250 ms 的回归预算 |

`pnpm check` 是前端统一入口。CI 在 Linux 运行前端检查与基准，在 macOS 运行原生检查和 `.app` 构建；不会自动发布。

## 4. UI 验收脚本

使用浏览器工具，按可访问名称操作。网页与桌面共用 UI；浏览器成功不能替代原生 IPC 验收。

1. 新建 `Harness 验收`，在「笔记内容」输入 `price=100\nprice+10%\n5 km to m`（实际换行）；结果为 100、110、5000 m。
2. 将 100 改为 200，核对 200、220；添加 `1/0` 后该行显示错误，后续 `3+4` 仍为 7。
3. 等待「已保存」，刷新；标题、正文、当前笔记恢复。搜索标题后可定位；移到废纸篓并恢复。
4. 在「计算器算式」输入 `200+10%`，按 Enter，核对结果 220 和历史；点击「写入当前笔记」，确认插入源算式并得到相同结果。
5. 验证 `2+3=` 后 `*4=` 得到 20；点击数字键、AC、退格和正负切换。计算器不得接管笔记中的正常输入。
6. 点击行结果复制；打开语法速查并用 Escape 关闭；导入测试文本，再导出比较正文。
7. 检查浅色/深色与 375、768、1280、1440 px 布局；没有页面横向溢出，长算式在编辑区域内滚动。查看浏览器控制台。
8. 原生窗口重复编辑/关闭/重开并验证真实文件；使用系统保存对话框导出测试笔记。
9. 点击侧栏设置行最右侧的太阳/月亮图标切换明暗（纸白/午夜），核对实际背景与文字即时切换、图标随模式变化；设置弹窗不再包含主题配色块；刷新后主题和计算器模式应恢复。核对版本、构建时间、GitHub 链接，侧栏不再出现旧离线文案。
10. 切换弹窗计算器，点击外部左/右/上/下区域关闭；Escape 关闭；重新打开算式和历史保留。检查连续点击数字时输入框焦点稳定，键盘 Tab/Enter 仍可操作按键。
11. 输入 `1/7`、`9999999999.999`、`-9999999999.999`、`12345678901`，核对三位小数、科学计数法和字体适配；结果区文本宽度不超过容器，无横向滚动条。
12. 在笔记中输入 `tax=3\nx=4\ntax x x\n{[18+24]x(3-1)}`，核对 3、4、12、84；变量名不得被 x 归一化破坏。
13. 在隔离的原生数据目录中选择空文件夹，核对当前笔记被复制、随后编辑只更新新位置、重启仍使用新位置；检查取消选择与已有不同工作区的冲突，双方文件应保留。

改 UI 时保存有代表性的截图到忽略的 `artifacts/`；在 [质量表](QUALITY_SCORE.md) 记录场景、环境、结果和未测内容。当前未把 UI 自动化接入远端 CI，不伪称端到端测试全自动。

## 5. 排错与维护

- 算错：先将最小原文加入 `tests/cases/calculations.json`，修复共享内核，不只修一个入口。
- 保存失败：先导出当前文本；保留 `workspace.json` 与 `.bak`。关闭应用后复制备份另存，确认内容再恢复。不要删除数据“修复”报错。
- 默认笔记目录为 `~/.calcbook/`；macOS 目录配置在 `~/Library/Application Support/com.tairraos.calcbook/settings.json`。当前实际笔记路径以设置界面为准；开发隔离目录由上述显式环境变量决定。
- 更换目录失败：先检查设置内错误；目标含不同工作区时请选择空文件夹。应用当前没有合并或覆盖已有工作区的流程，不删除目标文件绕过保护。
- 架构检查失败：错误中提供违规文件和修复方向，将 I/O 移回 platform，将业务计算移回 domain。
- 每次改变行为，同次更新契约、计划和质量证据；完成计划归档。发现重复的评审意见，把它变成最小的可运行约束。

文档新鲜度检查只是提醒，不替代语义核验。当前不创建后台自动任务或完整遥测系统；需要时再加。
